# Shape Morphing Engine Specification

> Built on top of the Geometry Kernel.

# Overview

The Morphing Engine transforms one complete shape into another. It
establishes geometric correspondence between contours before any
interpolation is performed. The engine itself does not decide how a
cubic is split---that responsibility belongs to the Geometry
Kernel---but it configures and orchestrates subdivision so that both
source and target remain synchronized.

Pipeline

    Shape A            Shape B
       |                  |
    Normalize        Normalize
       |                  |
    Rotate          Rotate
       |                  |
    Choose canonical start
            |
    Synchronous adaptive subdivision
            |
    Canonical cubic correspondence
            |
    Piecewise interpolation
            |
    Reconstruct output path

# Source and Target Rotation

Each shape may specify an initial rotation. Before correspondence is
computed, A is rotated around its own bounding-box center by θ₀ and B
around its own bounding-box center by θ₁. These rotations are not part
of the animation; they only improve the quality of correspondence by
bringing similar regions into alignment.

# Canonical Start Point

Contours are cyclic. After rotation, the engine draws a line joining the
contour centres and chooses the outermost intersection on each contour
as an initial candidate start point. If the point lies inside a
primitive (cubic, conic, arc, etc.), that primitive is split first so
the start becomes an explicit vertex. The contour sequence is then
rotated so both contours begin from corresponding locations.

# Synchronous Subdivision

The source and target are never subdivided independently.

Every split introduced in either contour is mirrored into the other
contour at the corresponding **normalized arc-length position**. This
guarantees that both contours are ultimately represented by the same
number of canonical cubic micro-segments covering identical fractions of
their total lengths.

Mandatory synchronization points include:

-   Original verb boundaries.
-   Canonical start point.
-   Cusps.
-   Inflection points.
-   Tangent discontinuities.

Additional subdivision generated by adaptive criteria is also propagated
to the other contour.

# Adaptive Splitting

Adaptive subdivision is configurable through a bit-mask in
`MorphOptions`. Every geometric test may be enabled or disabled
independently depending on the desired trade-off between geometric
accuracy and performance.

``` cpp
enum MorphSubdivisionFlags : uint32_t
{
    kSplitFlatness          = 1 << 0,
    kSplitTangentAngle      = 1 << 1,
    kSplitCurvature         = 1 << 2,
    kSplitInflection        = 1 << 3,
    kSplitCusps             = 1 << 4,
    kSplitArcLengthError    = 1 << 5,
    kSplitTurningAngle      = 1 << 6,
    kSplitMaxArcLength      = 1 << 7,
};
```

The engine first inserts all mandatory feature points (verb ends, cusps,
inflections, tangent discontinuities). It then recursively evaluates the
remaining enabled criteria. If **any** enabled test fails, the segment
is split and both children are re-evaluated.

## Flatness

Flatness measures how far a curve departs from the straight chord
joining its endpoints. For Bézier curves this is estimated from the
maximum perpendicular distance of the control points from the endpoint
chord.

Flatness is the primary criterion controlling tessellation density.
Long, almost straight curves remain a single segment while highly curved
regions subdivide until the deviation falls below `flatnessEpsilon`.

## Tangent Angle

Two curves with similar positions but very different endpoint tangents
morph poorly. This criterion compares the tangent direction at the
beginning and end of the interval. If the angular change exceeds
`tangentAngleEpsilon`, the interval is subdivided.

This is especially important near rounded corners and S-shaped curves
where flatness alone may underestimate geometric complexity.

## Curvature Variation

Curvature is sampled at several parameter values over the interval. The
engine computes the difference between the maximum and minimum sampled
curvature.

Large variation indicates that the curve bends at very different rates
across the interval. Such regions benefit from additional subdivision
because they are more difficult to approximate faithfully by a single
canonical cubic.

## Inflection Points

Inflection points are locations where curvature changes sign. Rather
than allowing one micro-segment to cross an inflection, the engine
solves for the inflection parameter and inserts an exact split there
before recursion continues. This produces segments with more uniform
curvature behaviour.

## Cusps and Loops

Cusps occur where the first derivative approaches zero, producing an
undefined or rapidly changing tangent. Self-loops also represent
topological changes that should not exist inside a single canonical
segment.

Whenever detected, these locations become mandatory subdivision points
regardless of other tolerances.

## Arc-length Error

The engine compares several length estimates, such as the endpoint
chord, control polygon length and numerical arc length.

Large disagreement implies that the interval contains significant
curvature and should be subdivided further. This criterion complements
flatness because two curves may have similar flatness while differing
substantially in true arc length.

## Maximum Turning Angle

The accumulated turning angle of the control polygon provides another
estimate of geometric complexity. If the control polygon rotates by more
than the configured threshold, the interval is split even if the other
tests pass.

This helps prevent long segments from spanning multiple visually
distinct bends.

## Maximum Micro-Segment Arc Length

Every accepted interval must also stay below the configured physical
arc-length cap. Unlike the geometric error tests, this criterion
subdivides perfectly straight verbs. It prevents long glyph edges from
corresponding to a single cubic while the other shape contains many
small curved pieces.

# Recursive Driver

Pseudo-code

``` cpp
Subdivide(segment)
{
    insertMandatoryFeaturePoints(segment);

    if (allEnabledTestsPass(segment))
    {
        emit(segment);
        return;
    }

    auto [left, right] = Split(segment);

    Subdivide(left);
    Subdivide(right);
}
```

# Piecewise Morphing

Each pair of canonical cubic micro-segments is interpolated
independently. Anchor points, control points and auxiliary metadata are
interpolated while translation, rotation and scale are handled
separately as transforms.

# Hole Handling

The outer contour is processed first.

Each hole centre is computed relative to the outer contour centre. Holes
are sorted by polar angle and matched pairwise between source and
target.

Unmatched source holes collapse into their centres before disappearing.
Unmatched destination holes grow outward from their centres.

Matched holes reuse the identical contour morphing pipeline.

Hole geometry is stored relative to the source and target outer-contour
centres. On every interpolated frame the engine measures each hole
against the current outer boundary. A hole that violates the configured
clearance is locally deformed inward; if local correction cannot restore
a valid contour, the hole is contracted toward a safe interior point.

# Intermediate Topology Guard

The interpolated outer contour is checked for non-adjacent boundary
intersections. A self-intersecting intermediate is simplified with Skia
Path Ops before holes are applied, so the returned path has non-crossing
outer boundaries and stable fill semantics.

# Skia Integration

Useful APIs include:

-   `SkPath::Iter`
-   `SkContourMeasureIter`
-   `SkContourMeasure`
-   `SkPath::transform`
-   `SkPath::addPath`

Exact feature detection (such as cubic inflection solving) is
implemented by the library when Skia does not provide a dedicated API.
